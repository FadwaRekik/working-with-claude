# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`ops-dashboard`: the Marlowe & Finch operations dashboard. A Spring Boot 3.2 / Java 17 read-only REST API over PostgreSQL, plus a vanilla-JS page (no framework, no build step) that calls it and draws KPI tiles, two inline-SVG charts, a late-deliveries table and a vendor list. The repo doubles as workshop material (`workshop/`, `docs/`); tickets live in `docs/tickets/`.

## Commands

```bash
./mvnw test                                      # Java suite: 25 tests (JUnit 5, H2, MockMvc)
./mvnw test -Dtest=DashboardControllerTest       # single Java test class (append #method for one method)
npm install                                      # once
npm test                                         # Frontend suite: 45 tests (Jest + jsdom)
npx jest src/test/javascript/render.test.js      # single Jest file (add -t "name" for one test)
SPRING_PROFILES_ACTIVE=demo ./mvnw spring-boot:run   # run on in-memory H2, no Docker needed
docker compose up -d db && ./mvnw spring-boot:run    # run on PostgreSQL 16 (default profile)
```

App serves on http://localhost:8080. Use the `demo` profile in Claude Code on the web.

## Architecture

- **Backend** (`src/main/java/com/marlowefinch/ops/`): controllers -> `DashboardRepository` / `VendorRepository` using plain SQL via Spring JDBC (no JPA). Responses are Java records. All endpoints are `GET` under `/api` (`/health`, `/kpis`, `/deliveries/on-time`, `/deliveries/late`, `/tickets/by-category`, `/vendors`); `from`/`to` are ISO dates defaulting to the last 30 days.
- **Schema and data**: Flyway migrations `V1__schema.sql` and `V2__seed.sql` (generated by `tools/make_seed.py`). The `demo` profile and all tests run the same migrations on H2 in PostgreSQL mode.
- **Pinned clock**: "today" is 2026-09-21 (`ops.today`, `ClockConfig`). Every default range and "days until" figure derives from the injected `Clock`; never use `LocalDate.now()`.
- **Frontend** (`src/main/resources/static/`): `app.js` wraps everything in `initApp(document, fetchImpl)` and exports via `module.exports` so the same code runs in the browser and in Jest. Colours currently live in `style.css`.
- **Jest harness** (`src/test/javascript/setup/loadApp.js`): loads `index.html` into jsdom, fakes every `/api` endpoint with fixtures, then starts the app. `REGISTERED_IDS` must list every element id in `index.html`; `harness.test.js` fails otherwise. Register any new id there.
